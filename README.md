# Automation Workflow Test Project

This project is a **Selenium + TestNG** based test automation framework designed to valid web application workflows. It attempts to be self-contained by including necessary tools (JDK, Maven) locally.

## 📂 Project Structure

Here is a breakdown of the folders and files in this repository:

### Root Directory
*   **`pom.xml`**: Only for Maven projects. This file defines the project's dependencies (Selenium, TestNG, etc.) and build configuration. It is the "brain" of the project's build system.
*   **`testng.xml`**: The test suite configuration file. It controls which tests run, their order, parallel execution settings, and listeners.
*   **`run_mvn.ps1`**: A PowerShell wrapper script to run Maven commands using the local `tools/` directory. Use this to run tests without installing Java/Maven globally.
*   **`setup_env.ps1`**: A setup script that extracts the embedded JDK and Maven from `tools/` if they aren't already ready. Run this once after cloning.
*   **`tools/`**: Contains the local binaries for **Java (JDK)** and **Maven**. This ensures every developer runs with the exact same versions, regardless of what is installed on their machine.

### Source Code (`src/test/java`)
The actual test code lives here, organized by packages:

*   **`base/`**: Contains `BaseTest.java`.
    *   **What**: The parent class for all tests.
    *   **Why**: It handles common setup (launching browser) and teardown (closing browser, generating reports) so you don't repeat code in every test.
*   **`pages/`**: Implements the **Page Object Model (POM)** pattern.
    *   **What**: Each class corresponds to a web page (e.g., `LoginPage.java`, `DashboardPage.java`).
    *   **Why**: To separate page interaction logic (locators, clicks) from test logic (assertions). If the UI changes, you only update the Page class, not the tests.
*   **`testing/`**: The actual Test classes (e.g., `ErrorHandlingTest.java`, `LoginTest.java`).
    *   **What**: These contain methods annotated with `@Test`.
    *   **Why**: This is where you define the test steps and assertions.
*   **`utils/`**: Helper headers and utilities.
    *   `ManualLoginHelper.java`: Helps handle login flows that might require manual intervention.
    *   `analytics/`, `health/`: Custom utilities for tracking test health and metrics.

### Artifacts (Generated)
*   **`target/`**: The build directory where Maven places compiled classes. (Ignored by Git).
*   **`test-output/`**: Default TestNG report folder. Contains `index.html` with test results.
*   **`reports/`**: Custom reports generated by the framework (e.g., health reports, trend charts).
*   **`screenshots/`**: Screenshots captured during test failures.

## 🚀 How to Run

### 1. Setup Environment
Open a terminal in the project root and run:
```powershell
.\setup_env.ps1
```
This prepares the local Java and Maven tools.

### 2. Run All Tests
To run the entire suite defined in `testng.xml`:
```powershell
.\run_mvn.ps1 test
```
*Note: If you encounter "execution policy" errors, run with:*
```powershell
powershell -ExecutionPolicy Bypass -File .\run_mvn.ps1 test
```

### 3. Run a Specific Test
To run a single test class (e.g., `ErrorHandlingTest`):
```powershell
.\run_mvn.ps1 test "-Dtest=testing.ErrorHandlingTest"
```
